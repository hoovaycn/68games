# 第二幕战斗地图绘制说明

开工目录：`docs/map/tiled_project/`。**主线必画 10 张**：ch10、ch11、ch12、ch13、ch14、ch15、ch15b、ch16、ch17、ch19。`ch18_battle1.tmx` 是旧存档兼容战斗，新主线从地下室直上钟楼，不经过此战，可以最后再画。

## 先看这四条

1. 当前战斗系统是 **1 逻辑格 = 1 个 48×48 瓦片**，TMX 的 `tilewidth/tileheight` 均为 48。虽然项目有 32×32 美术资源，现有第二幕运行时还没有完成 32 格或 3×3 子格换算，**这轮不要直接把 TMX 改成 32×32**。Tiled 打开视图网格并开启 **Snap to Grid**。
2. 每张图都有 `Background`（铺地）、`Decoration`（装饰）、`Spawns`（单位出生点）、`Collisions`（不可通行区域）四层。每个出生点是一个 48×48 矩形。**保持 Spawns 中对象的原有顺序和总数**：前 N 个对应表中我方，后 M 个对应敌方；拖动即可，不要删除后新建、也不要用排序修改对象次序。左右站位可换，角色身份由对象顺序决定。
3. 视觉上有墙、深水、毒池、整排货箱、船舷的地方，需在 `Collisions` 另画矩形；只画在装饰层不会挡路。浅水、掩体、高台等可站地形可另建 `Zones` 对象层，按对象名 `水坑`、`掩体`、`高台` 等配置，不能用 `Collisions` 封死。出发区、敌军区各留至少两条能互通的路线，宽度至少 1 格，常用通道建议 2 格；所有出生点不得落在碰撞区。
4. 绘完一图先保存，再运行 `node tools/sync_tmx_levels.cjs ch10_battle1`（替换成相应关卡 ID）回写 JS；完成所有图可无参数批量同步。脚本现在会检查图层、尺寸、出生点数、网格吸附、重叠和双方通路，出错会停止且不会覆盖该关卡 JS。**不要运行 `tools/build_act2_battles.cjs`、`tools/generate_tiled_maps.cjs` 等重新生成脚本**，它们会抹掉已绘制的瓦片。同步后运行 `npm test` 和 `npm run build`。

坐标采用从 0 开始的 `(x,y)`，左上角为 `(0,0)`。表中数字均是已经放置的出生点数量；你只需绘制/调整现有矩形，不要再额外新增同类点。前三个我方栏位在女线会自动映射为石予诺、陈品璇、何妍熹，其余队员共通。关卡启动前全员 HP/MP 会回满；敌方掉落包含 HP/MP 补给，道具可以留到后续战斗。

## 数值检查结论

- 第一幕末战为 6 对 6、敌方多在 5–8 级；第二幕前两战为 6 对 5、主要敌方 7–8 级。角色成长和存档延续，未强制统一等级，因此难度还会受第一幕经验分配影响。
- 中段以 5–9 名我方对 5–8 名敌方为主；大型战场 16×12 或 18×12，小型战场 16×10。重装死士保留约 36 HP，但已降低武器单次爆发；巨魔保留约 157 HP，近身反击已降低。每战开场回满 HP/MP，掉落有续航保障。
- 这是基于真实战斗公式、单位面板、出生点和地图连通性的配置审查，不等于人工完整通关或不同等级/路线下的胜率承诺。正式瓦片和碰撞布好后再测一次实际走位与回合数，尤其是 ch13 的闸口和 ch19 的核心路线。
